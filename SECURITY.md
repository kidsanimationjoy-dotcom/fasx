# Security Policy

## Supported development branch

Security fixes should target the current supported development branch and be reviewed before release.

## Reporting a vulnerability

Please do not publish credentials, private device information, or exploit details in a public issue. Use GitHub's private vulnerability reporting for this repository when available. If private reporting is not enabled, contact the repository owner privately before sharing sensitive details.

## Project security commitments

- Remote sessions must be visible and locally approved.
- No hidden access or secret persistence.
- Device pairing and session grants must expire and be revocable.
- Secrets must never be committed to the repository.
- Security-sensitive changes require tests and review.
